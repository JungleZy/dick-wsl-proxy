# 接管架构

**数据面的边界在 Windows，发行版的选择发生在 WSL 内核。** 同一 Windows 账户下只接管选定 WSL2 发行版的本地 Linux 进程，包括后台服务；其他发行版与 Windows 原生进程保持原网络行为。用户不配置应用代理，程序不修改 Windows 系统代理、WSL 共享默认路由或解析器文件。

**首版同一 Windows 账户最多接管一个发行版。** 界面选中的候选目标不等于实际接管目标。切换时可先只读预检新目标；预检通过后先停止并核实旧目标恢复，再对新目标写规则。旧目标清理未确认，不启动新目标。单目标约束由 Windows 后台执行，不依赖窗口是否打开。

| 边界 | 现行设计 |
|---|---|
| 发行版与宿主机 | Windows 控制器在目标上下文按 cgroup 安装带实例标识的临时引流规则。不按共享网卡、IP 或 UID 判定发行版。WSL 不部署常驻助手、Mihomo 或代理服务。 |
| Windows 入口 | 绑定 WSL 对应虚拟接口。以实际收到的协议和对端信息核对连接跟踪原始与回包元组，恢复原目标；无唯一且可归属的记录则拒绝。 |
| 默认系统 DNS | 启用接管即同时接管目标发行版的系统 DNS（UDP/TCP 53），无需另开开关。Windows 将查询经宿主代理和住宅出口送至指定 DNS 上游；必要的源地址转换只作用于被引流的查询。不修改共享 `resolv.conf`，也不改变其他发行版或 Windows 的 DNS。业务白名单不豁免解析；上游或代理不可用时，新查询失败，不回退到本地运营商或 Windows 默认解析器。 |
| 出站策略 | 白名单由 Windows 直接拨号；其他连接先通过宿主机已有代理入口连接静态住宅 SOCKS5，再由住宅连接最终目标。不限定首跳软件，不接管其机场订阅。协议不支持、链路故障或策略无法安全执行时不降级直连。 |
| 生命周期 | 窗口、Windows 后台和系统规则有独立生命周期。入口故障不是停止命令。主动恢复只处理本实例的规则、监听和经核对的映射；新流量恢复与旧 UDP 映射、TCP 排空或重连分开确认。 |

Windows 凭据不进入 WSL。WSL 内的特权操作仅限能力探测、临时规则及本实例映射的查询与清理。不把此方案作为对抗 Linux root 或本机管理员的安全沙箱。
