# 接管架构

**数据面的边界在 Windows，发行版的选择发生在 WSL 内核。** 同一 Windows 账户下只接管选定 WSL2 发行版的本地 Linux 进程，包括后台服务；其他发行版与 Windows 原生进程保持原网络行为（按发行版区分依赖内核：已在 WSL 内核 6.18.58.1 实测，目标内核更旧时预检阻断；规则经 `iptables-nft` 写入，因为 legacy 表每次写入都整表替换，内核会按执行写入的进程重新解析 cgroup，别的发行版一次 legacy 写入就会把规则改绑过去）。用户不配置应用代理，程序不修改 Windows 系统代理、WSL 共享默认路由或解析器文件。

**首版同一 Windows 账户最多接管一个发行版。** 界面选中的候选目标不等于实际接管目标。切换时可先只读预检新目标；预检通过后先停止并核实旧目标恢复，再对新目标写规则。旧目标清理未确认，不启动新目标。单目标约束由 Windows 后台执行，不依赖窗口是否打开。

| 边界 | 现行设计 |
|---|---|
| 发行版与宿主机 | Windows 控制器在目标上下文按 cgroup 安装带实例标识的临时引流规则。不按共享网卡、IP 或 UID 判定发行版。WSL 不安装 Mihomo、代理、服务或监听端口；接管期间只有一个由 Windows 经 `wsl.exe` 拉起、只走标准输入输出的只读查询进程，随接管结束退出。预检要求目标的 WSL 内核不低于已实测按发行版隔离的 6.18.58.1。 |
| Windows 入口 | 绑定 WSL 对应虚拟接口。以实际收到的协议和对端信息作为回包元组，向内核精确取默认 zone 中的那一条连接跟踪记录，核对原始与回包元组并恢复原目标；取不到或无法归属则拒绝。原目标是本次接管分配的假地址时换回对应的域名，假地址不认识或已回收则拒绝。TCP 并发与空闲期限按策略设上限，接管启动时固定；满载时拒绝新连接并记录，不排队。 |
| 默认系统 DNS | 启用接管即同时接管目标发行版的系统 DNS（UDP/TCP 53），无需另开开关。Windows 将查询经宿主代理和住宅出口送至指定 DNS 上游；必要的源地址转换只作用于被引流的查询。不修改共享 `resolv.conf`，也不改变其他发行版或 Windows 的 DNS。命中域名白名单的查询改由 Windows 直接经 DoH 问策略中的国内上游（默认 `223.5.5.5:443`，`dns.alidns.com`，可设为 `null` 关闭），让直连站点拿到国内视角的地址；该上游连不上或应答不可用（含 SERVFAIL、REFUSED 和会被白名单路径拒收的应答；NXDOMAIN 照常返回）时，仍经代理链问指定上游。其余查询一律经代理链。策略开启 fake-ip（默认开启，可在策略和桌面端关闭）时，白名单以外域名的 A 查询不再问上游，而是当场回答本次接管内分配的假地址（`198.19.0.0/16`，TTL 1 秒），AAAA 与 HTTPS/SVCB 回空应答，域名留到连接时交给住宅代理解析；单标签名字、`resolv.conf` 搜索后缀和特殊用途后缀下的名字、就绪探测名字、带 DNSSEC 标志的查询仍按上述方式解析。假地址每次接管从随机位置开始分配，满了只回收空闲 10 分钟以上、且本次接管内从没被连接过的地址，回收不到就改为问上游。住宅代理不接受按域名连接，或白名单别名已用到该网段的上半段时，本次接管不启用 fake-ip，原因记在就绪结果；启用时白名单别名只用 `198.18.0.0/15` 的下半段。经代理链（或国内上游）取得、通过校验的应答在本次接管内按 TTL 缓存（上限 1 小时；否定应答按 SOA）；过期后一小时内先返回旧应答（TTL 记为 30 秒），同时在后台刷新一次（刷新时上游正常回答却不让缓存，旧应答随即作废；上游失败时旧应答用到期满；同时最多 32 个刷新）；同时到来的相同查询只向上游问一次；就绪探测的域名不走缓存。上游或代理不可用时，缓存（含过期一小时内的旧应答）以外的新查询失败，不回退到本地运营商或 Windows 默认解析器。无法回答时回错误应答而不是不回：经上游的查询失败回 SERVFAIL，本地判定拒绝的查询回 REFUSED，格式不对但能读出 ID 和问题的回 FORMERR，错误应答不进缓存；fake-ip 应答在占用 DNS 工作线程之前当场给出。 |
| 出站策略 | 白名单只对 TCP 生效：命中白名单的 TCP 由 Windows 直接拨号；UDP（含 QUIC）不论是否命中白名单都不直连，同其他连接一样走双跳，目标访问的是白名单域名的别名地址时，交给住宅代理的是别名背后的真实地址，以免网页经白名单里的 STUN 服务器拿到 Windows 的真实出口；白名单里的内网地址因此收不到 UDP。其他连接先通过宿主机已有代理入口连接静态住宅 SOCKS5，再由住宅连接最终目标（唯一例外是用户确认后的「检测住宅代理」：从 Windows 直连住宅服务器认证一次，只用于检测，见决策 25）；目标是假地址时以域名交给住宅代理解析并连接，IP 白名单只对直接连 IP 的连接生效。不限定首跳软件，不接管其机场订阅。协议不支持、链路故障或策略无法安全执行时不降级直连：住宅端不支持 UDP 时拒绝全部 UDP（系统 DNS 除外），TCP 与 UDP 以外的协议一律丢弃；容器流量只接管目标里 Docker 的 bridge 网络（归属由目标内的客机脚本经 `docker.sock` 读出，只在目标有和它同一网络栈的 `dockerd` 进程时读；`dockerd` 停止期间已纳入的网络保留到网桥消失）：网段内互访不引流，其余 TCP/UDP 同本机流量一样引流，不能引流的在转发处丢弃（出不了本机的组播、受限广播和 IPv6 链路本地放行）；目标本机经该网桥访问该网络网段的流量（宿主机访问容器、端口映射）放行，IPv6 阻断模式除外；别的网桥（别的发行版的容器、认不出归属的）不引流也不拦截。启动时目标的网络在安装规则前读取、和基础规则同批提交；`dockerd` 在运行却始终读不出时启动失败、需要恢复，这时目标本机的流量已阻断，但目标的容器可能直连，界面如实提示。目标在规则装上之前就建立的连接不放行：本机只放行带本实例标记的已建立连接，目标发出的旧 TCP 连接再发包时被重置，应用重连后按新连接引流，旧 UDP 流丢弃；目标在接管启动时会重启，这类连接主要来自重启后、规则装上前就连上的开机自启程序。住宅认证与 CONNECT 合并发送，有近期请求时预建已认证的隧道，闲置上限只从在池里还没用就被关掉的隧道学习，10 分钟没再遇到就回到初始值；认证应答前连接就断开时停用合并发送并逐步重发；合并发送在本次接管中还没成功过时，CONNECT 无应答也会退回逐步发送一次。 |
| 生命周期 | 启动或切换到某个目标时，在预检通过、用户确认之后、装任何规则之前，Windows 经双跳查住宅出口所在时区，以 root 把目标的时区改成它并关掉 WSL 按 Windows 同步时区，然后只重启这个发行版：重启前在目标里写一个开机最早阶段执行的 systemd 单元和标记，目标一开机就只丢弃、不放行（没有 systemd 的目标做不到，确认框写明这段时间开机自启的程序会直连），引流规则装好、就绪后撤掉；等它的 systemd 启动完，再重新预检，之后都按重启后的目标来；每次都重启，时区本来就对也重启；查不到时区、目标缺这个时区的数据或查询域名在白名单里时不接管，切换时旧目标保持接管；停止接管不改回时区。窗口、Windows 后台和系统规则有独立生命周期。入口故障不是停止命令。接管期间定时只读核对目标里的本实例规则和连接映射，目标的 Docker 网络有增删时补、删对应规则；目标重启、规则缺失、环境变化，或出现带本实例标记却无法证明归属的映射时，转为需要恢复，不自动重装；其中本实例 filter OUTPUT 上的守卫不再排在别人的规则前面也算规则不全（各发行版 nft 后端的规则与本实例同表；nat 的链不查，它被挤到后面只会不通）；转发闸门放在 nft 的 mangle 表，Docker 重启时碰不到它，它被别人插到前面时转为需要恢复、不断网；核对每轮从目标发一个探测包，确认本实例按 cgroup 匹配的规则仍匹配目标，不匹配（别的发行版整表导回了含本实例规则的表）就在目标里原样重插这些规则，仍不匹配再按规则失效处理；规则缺失或不全和目标或 WSL 重启时，在目标当前环境里装一组按目标 cgroup 匹配的规则，目标本机进程新发起的连接除回环外全部丢弃（别人连进目标的连接的回包照常），同时在 mangle FORWARD 丢弃目标 Docker 网桥转发出去的流量，停止时一并删除，目标停着就等它下次运行再装，装不上时如实显示目标可能直连。控制器崩溃后，由拿着控制器锁的一方接手定时核对并执行同样的断网：没有控制器进程时是入口端口的持有进程，重新连接拉起的后台则自己做。主动恢复只处理本实例的规则、监听和经核对的映射：身份或环境变化不阻断删除，但只能按本实例标签精确删除，且只能证明已清空；带本实例标记却证明不了归属的映射也不阻断停止：规则照删，这些映射不动、记录条数。目标已注销时，由用户确认后只释放 Windows 侧端口与记录。新流量恢复与旧 UDP 映射、TCP 排空或重连分开确认。 |

Windows 凭据不进入 WSL。桌面配置与住宅凭据（含密码）保存在 EXE 同级的 SQLite 配置库，删除该库即删除这些设置，库本身不额外加密。接管在 WSL 内的特权操作仅限能力探测、临时规则及本实例映射的查询与清理，以及启动或切换前改目标的时区（`/etc/localtime`、`/etc/timezone` 和 `wsl.conf` 的 `[time] useWindowsTimezone`）并重启该发行版；用户在桌面端显式发起的环境管理（新建、编辑、备份、删除发行版）和经用户确认的内核环境准备（加载目标已有的模块、注册空表，并写入开机自动加载的模块列表与空表 oneshot）另以 root 执行，只在没有接管时可用。用户显式确认的「升级 WSL 平台」在 Windows 上运行 `wsl --update`，会终止所有发行版，同样只在没有接管时可用（决策 26）。Windows 后台只接受同一账户、且完整性级别不低于后台自身的进程连接；后台以管理员身份运行时，普通权限的进程连不上。连接记录只存在本机，不含域名和传输内容。桌面端检查更新时访问 GitHub（经已保存的宿主 SOCKS5，连不上再直连，不经住宅代理，可在设置里关闭）；用户确认的一键升级在普通权限的桌面进程里下载并核对安装包，再交给包里的安装器替换程序文件，只在没有接管时可用，不绕过 PowerShell 执行策略；桌面以管理员身份运行时不提供一键升级，因为安装目录和暂存目录都对当前用户的普通进程可写。不把此方案作为对抗 Linux root 或本机管理员的安全沙箱。
