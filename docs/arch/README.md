# 接管架构

**数据面的边界在 Windows，发行版的选择发生在 WSL 内核。** 同一 Windows 账户下只接管选定 WSL2 发行版的本地 Linux 进程，包括后台服务；其他发行版与 Windows 原生进程保持原网络行为。用户不配置应用代理，程序不修改 Windows 系统代理、WSL 共享默认路由或解析器文件。

**首版同一 Windows 账户最多接管一个发行版。** 界面选中的候选目标不等于实际接管目标。切换时可先只读预检新目标；预检通过后先停止并核实旧目标恢复，再对新目标写规则。旧目标清理未确认，不启动新目标。单目标约束由 Windows 后台执行，不依赖窗口是否打开。

| 边界 | 现行设计 |
|---|---|
| 发行版与宿主机 | Windows 控制器在目标上下文按 cgroup 安装带实例标识的临时引流规则。不按共享网卡、IP 或 UID 判定发行版。WSL 不部署常驻助手、Mihomo 或代理服务。 |
| Windows 入口 | 绑定 WSL 对应虚拟接口。以实际收到的协议和对端信息作为回包元组，向内核精确取默认 zone 中的那一条连接跟踪记录，核对原始与回包元组并恢复原目标；取不到或无法归属则拒绝。原目标是本次接管分配的假地址时换回对应的域名，假地址不认识或已回收则拒绝。TCP 并发与空闲期限按策略设上限，接管启动时固定；满载时拒绝新连接并记录，不排队。 |
| 默认系统 DNS | 启用接管即同时接管目标发行版的系统 DNS（UDP/TCP 53），无需另开开关。Windows 将查询经宿主代理和住宅出口送至指定 DNS 上游；必要的源地址转换只作用于被引流的查询。不修改共享 `resolv.conf`，也不改变其他发行版或 Windows 的 DNS。命中域名白名单的查询改由 Windows 直接经 DoH 问策略中的国内上游（默认 `223.5.5.5:443`，`dns.alidns.com`，可设为 `null` 关闭），让直连站点拿到国内视角的地址；该上游连不上或应答不可用（含 SERVFAIL、REFUSED 和会被白名单路径拒收的应答；NXDOMAIN 照常返回）时，仍经代理链问指定上游。其余查询一律经代理链。策略开启 fake-ip（默认开启，可在策略和桌面端关闭）时，白名单以外域名的 A 查询不再问上游，而是当场回答本次接管内分配的假地址（`198.19.0.0/16`，TTL 1 秒），AAAA 与 HTTPS/SVCB 回空应答，域名留到连接时交给住宅代理解析；单标签名字、`resolv.conf` 搜索后缀和特殊用途后缀下的名字、就绪探测名字、带 DNSSEC 标志的查询仍按上述方式解析。假地址每次接管从随机位置开始分配，满了只回收空闲 10 分钟以上、且本次接管内从没被连接过的地址，回收不到就改为问上游。住宅代理不接受按域名连接，或白名单别名已用到该网段的上半段时，本次接管不启用 fake-ip，原因记在就绪结果；启用时白名单别名只用 `198.18.0.0/15` 的下半段。经代理链（或国内上游）取得、通过校验的应答在本次接管内按 TTL 缓存（上限 1 小时；否定应答按 SOA）；过期后一小时内先返回旧应答（TTL 记为 30 秒），同时在后台刷新一次（刷新时上游正常回答却不让缓存，旧应答随即作废；上游失败时旧应答用到期满；同时最多 32 个刷新）；同时到来的相同查询只向上游问一次；就绪探测的域名不走缓存。上游或代理不可用时，缓存（含过期一小时内的旧应答）以外的新查询失败，不回退到本地运营商或 Windows 默认解析器。 |
| 出站策略 | 白名单由 Windows 直接拨号；其他连接先通过宿主机已有代理入口连接静态住宅 SOCKS5，再由住宅连接最终目标；目标是假地址时以域名交给住宅代理解析并连接，IP 白名单只对直接连 IP 的连接生效。不限定首跳软件，不接管其机场订阅。协议不支持、链路故障或策略无法安全执行时不降级直连：住宅端不支持 UDP 时拒绝非白名单 UDP，TCP 与 UDP 以外的协议一律丢弃；容器流量只接管目标里 Docker 的 bridge 网络（归属由目标内的客机脚本经 `docker.sock` 读出，只在目标有和它同一网络栈的 `dockerd` 进程时读；`dockerd` 停止期间已纳入的网络保留到网桥消失）：网段内互访不引流，其余 TCP/UDP 同本机流量一样引流，不能引流的在转发处丢弃（出不了本机的组播、受限广播和 IPv6 链路本地放行）；目标本机经该网桥访问该网络网段的流量（宿主机访问容器、端口映射）放行，IPv6 阻断模式除外；别的网桥（别的发行版的容器、认不出归属的）不引流也不拦截。住宅认证与 CONNECT 合并发送，有近期请求时预建已认证的隧道；认证应答前连接就断开时停用合并发送并逐步重发；合并发送在本次接管中还没成功过时，CONNECT 无应答也会退回逐步发送一次。 |
| 生命周期 | 窗口、Windows 后台和系统规则有独立生命周期。入口故障不是停止命令。接管期间定时只读核对目标里的本实例规则和连接映射，目标的 Docker 网络有增删时补、删对应规则；目标重启、规则缺失、环境变化，或出现带本实例标记却无法证明归属的映射时，转为需要恢复，不自动重装。主动恢复只处理本实例的规则、监听和经核对的映射：身份或环境变化不阻断删除，但只能按本实例标签精确删除，且只能证明已清空；带本实例标记却证明不了归属的映射也不阻断停止：规则照删，这些映射不动、记录条数。目标已注销时，由用户确认后只释放 Windows 侧端口与记录。新流量恢复与旧 UDP 映射、TCP 排空或重连分开确认。 |

Windows 凭据不进入 WSL。桌面配置与住宅凭据（含密码）保存在 EXE 同级的 SQLite 配置库，删除该库即删除这些设置，库本身不额外加密。接管在 WSL 内的特权操作仅限能力探测、临时规则及本实例映射的查询与清理；用户在桌面端显式发起的环境管理（新建、编辑、备份、删除发行版）和经用户确认的内核环境准备（加载目标已有的模块、注册空表，并写入开机自动加载的模块列表与空表 oneshot）另以 root 执行，只在没有接管时可用。Windows 后台只接受同一账户、且完整性级别不低于后台自身的进程连接；后台以管理员身份运行时，普通权限的进程连不上。连接记录只存在本机，不含域名和传输内容。不把此方案作为对抗 Linux root 或本机管理员的安全沙箱。
