# 设计方案：检查更新与一键升级

> 2026-11-25。编译和发布已经全部在 GitHub 流水线上完成（[M5「发布流水线」](../plans/m5/README.md)），负责人问能不能做「检测到新版本 → 提醒 → 点按钮自动升级」。M5 原先写明交付形式「不是自动更新器」，所以这是设计变更。
>
> **负责人答复（2026-11-25）：按推荐方案做一键升级，不绕过 PowerShell 执行策略。** 已登记为[决策 31](../decisions.md)，实现与验证见 [M8](../plans/m8/README.md)。

## 结论

能做，推荐做成「桌面检查 → 提醒 → 确认后下载、核对，交给包里的安装器升级」：

1. 桌面打开 15 秒后查一次 GitHub，之后每天一次，设置里可以关；也可以手动查。
2. 有新版本时提醒一次，「设置 › 关于」显示新版本和「升级到 vX」按钮。
3. 点按钮并确认后：在桌面进程里下载 ZIP、核对 SHA-256；拉起一个独立的 PowerShell 进程，桌面退出；那个进程等桌面退出后解压、运行新包的 `install.ps1`、写下结果，再重新打开桌面，新打开的桌面显示升级结果。

不在 Rust 里重写安装器。文件替换的事务、回滚、`-Recover`、拒绝降级、拒绝接管中升级，全部沿用已经验收过的 `install.ps1`。

## 已确认的事实

| 事实 | 依据 |
|---|---|
| GitHub 的「最新版本」接口拿不到我们的版本 | 每个版本都以预发布发布（`release.yml` 的 `--prerelease`）；`GET /repos/…/releases/latest` 实测返回 404。只能列出发布、自己挑版本号最大的 |
| 每个版本有两个附件 | `wsl-proxy-<版本>-windows-x64.zip`（0.1.11 是 43,189,826 字节）和同名 `.sha256`（`<64 位十六进制>  <文件名>`） |
| 附件下载会跳转到另一个域名 | `github.com/…/releases/download/…` 302 到 GitHub 的下载域名（`*.githubusercontent.com`） |
| GitHub 接口不带 User-Agent 会拒绝；未登录每个 IP 每小时 60 次 | GitHub REST 文档；共用出口时可能被限流 |
| 安装器要求桌面窗口已关、后台空闲 | `common.ps1` 的 `Assert-GuiClosed`、`Close-IdleBroker`：桌面开着、接管中、需要恢复时都拒绝，而且从不结束进程 |
| 安装器会整体移动安装目录 | 升级时把安装目录移到 backup、把 stage 移进来；桌面开着时 `desktop.sqlite` 被占用，移动会失败。所以桌面必须先退出 |
| Windows 家庭版、专业版默认不允许运行 `.ps1` | 执行策略缺省是 Restricted；README 一直要求「在允许运行该脚本的 PowerShell 里执行，不要为此改执行策略」 |
| 程序自己写盘的文件没有「来自网络」标记 | 标记由浏览器等下载工具加；没有标记时 RemoteSigned 允许运行本机脚本 |
| 后台可能以管理员身份运行 | 决策 21：这时普通权限的进程连不上它；让后台替界面下载并执行安装，等于借后台提权 |
| 后台已有手写的 HTTPS 代码，但不够用 | `src/environment/timezone.rs`：最多收 64 KB、不跟随跳转、不支持分块传输、不带 User-Agent |

## 需要定的几点和结论

| 问题 | 结论 | 理由 |
|---|---|---|
| 一键升级还是只提醒（按钮打开发布页） | 一键升级 | 负责人选定。只提醒改动小，但用户仍要自己找包、核对、解压、运行脚本 |
| 执行策略不允许运行脚本时怎么办 | 不加 `-ExecutionPolicy Bypass`；先读当前生效的策略，只有 RemoteSigned、Unrestricted、Bypass 时才继续，否则说明原因、让用户从发布页手动升级 | 绕过会推翻 README 的一贯说法；用 `install.ps1` 装过的机器，策略本来就允许 |
| 下载放在哪个进程 | 桌面（普通权限）自己下载、核对，不经后台 | 决策 21 关掉的就是「后台替低权限界面办事」这条路 |
| 走哪条网络 | 已保存的宿主 SOCKS5 优先，连不上再直连；不经住宅代理 | 国内直连 GitHub 下载附件常常很慢或断；住宅代理和更新无关，不该为它消耗住宅流量或暴露住宅出口 |
| 怎么证明包没被换 | 只核对发布页公布的 SHA-256 | 包没有签名；校验文件和包来自同一处，只能发现下载损坏。信任前提和手动下载一样是 GitHub 的 TLS 加仓库账号。构建来源证明（attestation）要在程序里验证 Sigstore，首版不做 |
| HTTP 客户端 | 不加新的库，在 `native-tls` 上补跟随跳转（只限 GitHub 的域名）、分块传输、User-Agent、边下边写盘 | 新库会牵动许可证检查和第三方清单；需要的功能很少 |
| 哪些副本能一键升级 | 只有安装器装的：EXE 旁边有安装记录 `.wsl-proxy-install.json`、记录的目录就是当前目录、没有未完成的安装事务 | 直接解压运行或自己编译的副本没有可交给安装器的安装目录，只提醒 |
| 自动检查默认开还是关 | 默认开，设置里可关 | 负责人要的就是提醒；每次检查会让 GitHub 看到出口 IP，设置页写明 |

## 不做的

- 不静默升级：每次升级都要用户点按钮并确认。
- 不降级，不跳过安装器的任何检查。
- 不在接管中、需要恢复时升级；不替用户停止接管。
- 不提权，不改执行策略，不改 PATH、快捷方式或注册表（「自动检查更新」开关本身记在 `HKCU\Software\WSLProxyLab`，和主题设置同一个键）。
- 0.1.11 及更早的版本没有这个功能，要手动装一次带它的版本。
