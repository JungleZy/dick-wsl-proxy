# 设计方案：屏幕顶部状态岛

托盘图标太小，不够醒目，所以在屏幕顶部正中常驻一个黑色的岛。
- **外观**参照 Apple 灵动岛。
- **吸顶形态**参照岛仔的「刘海」（见 `2026-11-25-界面参考-岛仔组件清单.md`）：顶边贴住屏幕顶边，左右上角各有一段向内凹的圆弧（下称「肩」），和屏幕边缘平滑接上。
- **行为**：平时显示接管状态；状态变化或有提醒时自动展开几秒；鼠标移上去会带回弹地展开成卡片，卡片上能直接操作。

## 已定的取舍

| 项 | 结论 | 来源 |
|----|------|------|
| 显示方式 | 常驻小药丸。状态变化、有提醒时自动展开，鼠标悬停时展开 | 维护者选定 |
| 开关 | 托盘菜单「显示顶部状态岛」（勾选项），以及设置 →「桌面运行」→「屏幕顶部状态岛」，默认开。存在 `HKCU\Software\WSLProxyLab` 的 `DesktopIsland` 下，与主题偏好放在一起 | 维护者选定 |
| 点击 | 点岛本身不做任何事，只有卡片上的按钮有动作（「打开主窗口」是其中一个按钮） | 维护者要求 |
| 位置 | 在岛的空白处按下后一移动就开始拖；在按钮上要按住约 0.4 秒才拖，只能沿屏幕顶边左右移动，始终吸顶。松手后记住位置，存为窗口中心在主显示器宽度上的比例（`DesktopIslandPosition`，乘以 10000），换分辨率后按比例摆回 | 维护者要求长按拖动；只沿顶边移动是默认方案 |
| 全屏应用 | 前台是全屏程序（游戏、演示、浏览器全屏视频）时隐藏，退出全屏后再显示。判断依据是 `SHQueryUserNotificationState` | 默认方案 |
| 显示器 | 只放在主显示器顶部正中 | 默认方案 |
| 托盘规则 | 不变。托盘没显示时关窗照常退出，岛不能代替托盘作为找回主窗口的入口 | 默认方案 |
| 配色 | 跟随软件主题：深色主题是纯黑岛，浅色主题是浅灰白岛（`#f5f5f7`）配深色字；状态色取对应主题的状态色。软件里切换主题后，最多 0.2 秒岛就跟着变 | 维护者要求 |

## 显示内容

**收起时（184×32，不含两肩）**
- 中间留空，内容只放在左右两端，和 Apple 灵动岛一样。
- 左端：盾牌状态图标。接管中是实心盾牌带勾；需要恢复、状态未确认是感叹号；处理中是省略号；未接管是空心盾牌。
- 右端：状态简称，例如「直连」「需恢复」「未连接」「处理中」；接管中改为显示下行速率，例如「↓ 1.2M/s」。

**展开时（356×132，接管中 356×214；底部圆角 30）**
- 布局按内容排紧：四周 14 到 16px 边距，标题 15px，说明 12px，按钮高 36px。
- 左上：38px 的圆形徽章，底色是状态色淡化后的颜色，里面是盾牌图标。
- 徽章右边：标题，写状态，例如「接管中」；标题下是灰色说明，写目标发行版、进行中的操作或提醒内容，最多两行。
- 右上：接管中显示上下行速率。
- 接管中，标题区下面多两行被接管环境的信息，说法和首页一致：
  - 一整行「公网出口」：IP · 国家 · 与住宅地址一致／不一致／未比对；不一致用待处理色。没检测过显示「未检测」。
  - 三格并排：DNS（已接管时显示启动时测到的延迟，未接管用待处理色）、UDP（经代理链／已阻断／未确认）、连接（正在转发的 TCP 连接数）。
- 底部：一排等宽胶囊按钮。三颗按钮并排时托盘菜单的长说法放不下，岛上用短说法：「停止接管」「检测出口」「选择目标」「重新连接」「放弃记录」「打开主窗口」。
  - 主操作用实心状态色；「停止并恢复直连」「放弃本次记录」这类会断开连接的操作用红色。
  - 其余按钮是半透明白底。
  - 按钮包括：托盘菜单里的主操作；「检测公网出口」，只在接管中出现；「打开主窗口」。

**接管中的强调（2026-11-27 加）**
- 接管中（绿）岛的主体左、右、底三边描一圈淡绿边，再有两道光沿轮廓从右肩绕过底边流到左肩，一圈 3.2 秒，两道相隔半圈，任何时候边上都有光。光头在深色岛上偏白，在浅色岛上是饱和的绿。收起、展开都有。
- 只看是不是接管中：界面在读详情、等确认这类短暂操作不让描边消失。
- 系统设置了「减少动态效果」时只留描边（加深），光不流动。

**接管中展开时的应用胶囊（2026-11-27 加，参照岛仔展开时面板旁边的未读图标胶囊）**
- 卡片右边隔 8px 另起一条 48px 宽的竖胶囊，列出被接管环境里装的图形应用（和环境页「已安装应用」窗口同一份来源），每格 38px、图标 28px，没有图标的写应用名首字。
- 高度按格数收紧，最高和卡片齐平，再多就用滚轮在胶囊里滚动。
- 悬停一格时卡片的说明行换成「启动 某应用」；点一下以默认用户启动，主窗口不出来，结果（已启动／失败原因）作为提醒显示在岛上。同一时间只启动一个；主窗口有操作在进行（包括停止、切换接管）时不能启动，免得应用落进已经恢复直连的环境。
- 读取中转圈；读失败放一颗重试按钮，悬停显示原因；读到空列表时不显示胶囊。
- 每次接管只读一次列表，接管结束就清空：图标是 `\\wsl.localhost` 下的文件，停止后再去读会把发行版拉起来。

**形状**
- 顶边贴住屏幕顶边，左右上角的肩各是一段半径 12px 的四分之一凹圆弧，把竖直侧边接到屏幕顶边。
- 只有底部两个角是圆角。

**动画**
- 按临界阻尼弹簧运动：起步快、收尾慢，约 0.35 秒基本到位，全程不冲过头，停下时没有抖动。
  - 之前用带回弹的弹簧，展开到位后会冲过头再落回，看起来像抖了一下，所以改掉。
- 内容切换：收起的内容在形变一开始就淡出，展开的内容在形变后段才淡入，两者不会同时出现；淡入淡出用平滑曲线，不是线性。
- 拖动中岛半透明，表示已经拿起来了。
- 系统设置了「减少动态效果」时，不播放动画，直接切换。

**状态颜色**
- 绿：接管中
- 黄：诊断转发中、后台状态未确认、有操作正在进行
- 红：需要恢复
- 灰：未接管

## 自动展开规则

- 后台状态从一种变成另一种时展开 5 秒。程序刚启动、第一次确认状态时不展开。
- 变成「需要恢复」或「后台状态未确认」时展开 10 秒。
- 主界面弹出提醒时，岛同样展开显示这条提醒：普通提醒 5 秒，警告类 10 秒。
- 鼠标在岛上时一直保持展开；移开 0.4 秒后收回。

## 实现要点

- **数据来源**：直接用托盘的 `Snapshot`，另外带上最新一次流量采样作为速率，接管中再带上从后台状态里摘出的出口、DNS、UDP、连接数，以及当前是否深色主题。界面每 200ms 刷新时交给岛。
- **操作**：按钮和托盘菜单走同一条路，先叫出主窗口，再把 `Command` 交给界面处理。需要确认的操作（停止、放弃记录）照旧在主窗口弹确认框，岛里不另写一套状态判断。
- **窗口**：gpui 的 `PopUp` 窗口，置顶、不占任务栏，背景透明，贴着主显示器顶边居中。
  - 窗口大小固定，等于卡片加两侧的肩，再留一圈余量；形变动画只在窗口内部画，不改窗口大小。
  - 主体用底部带圆角的 div 画。每个肩用一个黑色粗边框的正圆环，再用方框裁出四分之一，圆环内圈就是那段凹弧。
    - gpui 的任意路径只有 4 倍多重采样抗锯齿，边缘看得出台阶；圆角和边框是逐像素计算的抗锯齿，边缘和主体一样顺滑。
  - 每一帧用 `CreatePolygonRgn` 和 `SetWindowRgn` 把窗口区域裁成当前轮廓，轮廓往外多扩 1.5px，给边缘抗锯齿留位置。这样透明的地方不挡下面窗口的点击。设区域时不要求系统重绘，重绘交给 gpui 的下一帧，避免闪动。
  - 关掉 Windows 11 默认加的灰色边框和系统圆角。
- **悬停**：岛自己每 33ms 比较一次光标位置和主体矩形（展开时加上应用胶囊）。
  - 鼠标离开窗口时 gpui 不会触发悬停回调，所以不能靠 `on_hover`。
  - 每 200ms 查一次前台是否全屏，同时检查窗口是否还在应在的位置。
- **拖动**：在岛上按下主键时记下光标和窗口位置，之后每帧检查。
  - 在空白处：一移动超过 6px（或按住满 0.4 秒）就开始拖。
  - 在按钮上：按住满 0.4 秒才开始拖；没到时间就移动，算放弃这次按下，按钮不触发。拖完松手时那次点击会被吞掉。
  - 判断主键是否还按着：既看 gpui 的鼠标抬起事件，也每帧用 `GetAsyncKeyState` 查。用户对调过左右键时改查物理右键，因为这个函数看的是物理按键。
  - 拖动中每帧横向移动窗口，不离开顶边，不出主显示器。
- **流动的光**：静止的描边用 div 边框画（逐像素抗锯齿），单独一层，从肩的圆弧收拢处（往下 12px）才开始，再往上的外沿是肩的圆弧，主体那段竖直边在形状里面，不描；肩的圆弧另用一条贴着凹弧内侧的细圆环描同样的颜色，和竖直描边接上。描边宽度取整 1px：边框会被对齐到像素，圆环不会，宽度带小数时两者错开半个像素，接缝处出一个折角。流动的光用 gpui 路径沿静止描边的中线描线（两侧往里半个描边宽，肩是和静止圆弧同一个圆心的凹弧），光经过肩部时和描边重合，每道光切成 12 段、从尾到头逐段变亮。只在接管中、岛没被全屏程序藏起来、没有减少动态效果时按看光标的节拍重画（约每秒 30 帧），不跟显示器刷新率一直重画。
- **窗口区域的原点**：`SetWindowRgn` 的坐标从窗口矩形左上角算，岛画在客户区里；这个窗口的窗口矩形比客户区左右各宽 8px（系统留的看不见的边框），所以区域和看光标都先加上客户区相对窗口矩形的偏移（`ClientToScreen`），居中也按窗口矩形的实际宽度算。不加时岛右边约 8px（右侧描边和右肩）被裁掉，悬停判定也偏左 8px。
- **应用胶囊**：窗口两侧各加宽一个胶囊的位置（卡片仍居中）；窗口区域是轮廓和胶囊圆角矩形（`CreateRoundRectRgn`、`CombineRgn`）的并集。胶囊上的点击记成一条请求，界面下次刷新时取走，按接管目标发 `environment_apps`／`environment_launch`，和环境页的应用列表各用各的状态。
- **找主窗口**：托盘按进程找主窗口时排除岛的窗口句柄，否则「显示主窗口」「隐藏主窗口」「退出」可能作用到岛上。
- **退出**：主窗口真正关闭时同时关掉岛，否则 gpui 还有窗口开着，进程不会退出。

## 试验记录（Windows，2560×1600，缩放 100%）

| 检查项 | 结果 |
|--------|------|
| 透明圆角 | 圆角外透明，没有黑边 |
| 居中贴顶 | 主显示器顶部正中，距顶边 8px |
| 任务栏 | 不出现 |
| 灰色边框 | 起初有一圈 1px 灰边；设置 `DWMWA_BORDER_COLOR = DWMWA_COLOR_NONE` 后消失 |
| 展开（初版做法，已不用） | 先用 gpui `resize` 改大小、再用 Win32 改位置，可以展开并保持居中；但动画每一帧都改窗口大小，所以改成固定窗口大小加裁剪窗口区域 |
| 鼠标移开 | `on_hover` 收不到，改用轮询光标位置 |
| 刘海形态 | 实际运行看过：顶边贴屏、两肩凹弧接上屏幕边缘、展开时有形变过程。改用圆角和边框绘制后，放大 4 倍看边缘顺滑 |
| 拖动 | 用模拟鼠标测过：在空白处按下后立刻右移，岛跟着移动 240px，位置写进了注册表 |
| 点击不打开主窗口 | 先把主窗口最小化，再用模拟鼠标点岛的空白处和拖动；两次之后主窗口都还是最小化 |
| 浅色主题 | 把软件主题设成浅色后重新启动，收起和展开都是浅灰白底、深色字 |
| 岛上的按钮 | 点「选择接管目标」，主窗口被叫出来并跳到「环境」页 |
| 流动描边和应用胶囊（2026-11-27） | 没有真实接管，用临时注入的演示数据（接管中、7 个应用，其中两个没有图标；另看了读取失败和只有两个应用）在深色主题下截图看过：收起和展开都有描边和流动的光；胶囊在卡片右边，高度随应用数收紧，滚轮能滚到后面的应用，悬停时说明行换成「启动 某应用」；光标从卡片移到胶囊上岛不收回（三次里有一次收回，之后没复现）。截图时发现并修掉了右边 8px 被裁的问题（见实现要点）。浅色主题、点击启动、真实图标路径（`\\wsl.localhost`）没看。演示代码看完已删除 |
| 接管中的卡片 | 真实接管没能启动：目标设为 `WSLProxyLab-Target`，预检通过，但启动时后台报「住宅服务器信息不完整」（住宅代理还没填地址、端口、用户名和密码）。改用临时注入的演示数据看了深色、浅色两种卡片：出口一行、DNS / UDP / 连接三格都正常；发现「停止并恢复直连」放不下，改成短说法。演示代码看完已删除 |
