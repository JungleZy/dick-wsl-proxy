# 设计决策

编号固定。决定被取代时保留原条目并标明取代者；现行约束以[接管架构](arch/README.md)为准。

| 编号 | 状态 | 决策 | 依据 |
|---|---|---|---|
| 01 | 已确认 | 同一 Windows 账户下按发行版 cgroup 临时引流；不在 WSL 安装代理或常驻助手。Windows 用连接跟踪信息还原原目标，无法唯一核实时拒绝。 | 两发行版可产生相同五元组，单看 Windows 包无法可靠归属；临时规则可区分目标的前台与后台。 |
| 02 | 已确认 | Windows 运行 GPUI 控制台和转发后台。白名单直连；其余复用宿主机已有代理作为第一跳，由本程序配置住宅 SOCKS5 作为第二跳。 | 不重复导入订阅，不绑定 TrojanX 或 Clash Verge；宿主代理握手与公网双跳分别验收。 |
| 03 | 已确认 | 故障保留阻断，只有主动停止才恢复原网。按实例精确撤规则与映射，分别确认新流量、旧 UDP 和存量 TCP。 | 删除规则后，旧 UDP socket 仍可命中原入口；启用前的直连 TCP 不会自动迁移。 |
| 04 | 已确认 | 系统 DNS 是目标发行版默认接管的一部分，与业务流量一起启停。未缓存查询须经配置的代理链访问指定上游；DNS 未就绪不得报告接管成功，不降级为本地解析。 | [Net.Coffee 对照](discussions/netcoffee-paired-results.md)：仅代理网页时，Target 仍使用与 Control 相同的中国电信递归出口；接管系统 DNS 后，Target 查询走指定上游，同期 Control 不变。 |
| 05 | 已确认 | 首版同一 Windows 账户一次最多接管一个 WSL2 发行版，允许切换。先确认旧目标恢复，再对新目标启用业务与 DNS 接管；不支持并行接管或无缝迁移连接。 | 用户确认首版范围；确保旧目标的残留规则、连接映射和异步操作不会影响下一目标。 |
| 06 | 已确认 | 受管接管期间定时只读核对目标（诊断用的 scoped 模式除外）：约每 30 秒确认目标仍注册；目标在运行时，再确认本实例规则齐全且身份一致。规则缺失、目标或 WSL 重启、环境变化（改名、地址变化、cgroup 外出现进程等）即转为需要恢复，保持到显式停止，不自动重装。不唤醒已停止的目标；扫描竞态、工具缺失等瞬时情况和检查本身失败不改状态。这是事后发现，不是事前防护。 | WSL 虚拟机重启会清空内存中的规则，此前状态仍显示接管中、目标流量已直连。从目标重启到下次检查之间，最长约 30 秒的新连接可能未经代理。 |
| 07 | 已确认 | 停止与恢复时，删除和核对规则不要求实例身份完全一致：任何身份或环境变化只记录原因，仍只删除本实例精确标签的规则与连接映射，且只能证明「已清空」；预检、安装与授权仍对任何变化拒绝。目标已注销时，由用户确认后放弃记录：只释放 Windows 侧端口与恢复记录，WSL 中可能残留的规则随下一次 `wsl --shutdown` 消失。 | 此前目标改名、注销或地址变化后停止永远失败，文档又禁止手删记录，用户没有出路。取代 [M1 执行记录](plans/m1/README.md)中「不以旧身份删除现有内核对象」的保守策略。 |
| 08 | 已确认 | DNS 别名账本里有未写完的修改时，禁止任何新分配；只有空闲时经确认的重置可以把它连同整个账本一起清空，清空时最后删除这条未完成记录。 | 此前这一状态无法恢复，白名单域名一直解析失败。重置的风险与普通重置相同：旧别名可能分给别的域名，确认时要求先重启目标或等别名过期。 |
| 09 | 已确认 | 每次接管的 TCP 并发、空闲断开和半关闭等待都有上限，默认 256 条、30 分钟、60 秒，可在策略中配置，启动或切换时固定。达到上限时拒绝新连接并计数、记录，不排队、不降级。 | 原先固定的 64 条、120 秒、15 秒会切断空闲 SSH、数据库连接池和长时间无返回的请求，且满载时静默断开。 |
| 10 | 已确认 | 启动时住宅 UDP 关联探测不通过，接管照常：本次接管期间非白名单 UDP（含 QUIC）一律拒绝、不直连，下次启动或切换时重新探测；系统 DNS 与 TCP 不受影响。 | 不少住宅 SOCKS5 只支持 CONNECT。为此让 TCP 和 DNS 也无法接管代价过大；拒绝而不是直连，维持决策 03 的故障阻断。 |
| 11 | 已确认 | 受管接管期间，目标发出的 TCP、UDP 以外的协议（ICMP 等）一律丢弃。 | SOCKS5 不能转发这些协议，放行就等于从本地出口直连。 |
| 12 | 已确认 | 桌面端提供 WSL 环境管理（新建、编辑、备份、删除发行版），只在没有接管时可用，作为后台任务执行。编辑只改本工具负责的 `/etc/wsl.conf` 键，并保留修改前的一份备份；新建失败只注销本次新建的注册。只有带 apt 的发行版会自动安装 systemd、iptables 和可选组件，其他发行版缺的工具由预检报告。 | 降低准备目标发行版的门槛。它以 root 修改发行版，扩大了 WSL 内特权操作的范围，见[接管架构](arch/README.md)。 |
| 13 | 已确认 | 桌面后台把受管接管中已结束的连接写入本机配置库，最多保留最新 50,000 条：记录目的 IP 与端口、协议、路由与原因、状态与失败阶段、字节数、起止时间和目标发行版，不含域名、DNS 内容和传输内容。写入失败只计数，不影响转发；脱敏诊断导出不含这些记录。 | 连接页需要可回看的历史。域名白名单连接记录的目的地址是合成别名地址，不是真实 IP。 |
