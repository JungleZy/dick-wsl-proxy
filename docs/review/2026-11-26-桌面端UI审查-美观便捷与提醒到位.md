# 桌面端 UI 审查（讨论稿）：美观、便捷与提醒到位

> 审查对象：HEAD `fb9a4fd`（v0.1.16），工作区干净。
> 审查日期：2026-11-26。
> **证据边界**
> - 静态读了 `desktop/src/app/` 全部界面代码，对照了 `design/ui-design-spec.md`。
> - 在 Windows 上用 Windows 工具链编译了 HEAD（`cargo build --locked --release -p wsl-proxyctl -p wsl-proxy-desktop`），拷到 `D:\WSL\ProxyLab\ui-review-20261126\` 用全新配置启动，截了 20 张图，放在同目录 `shots\`。
> - 截图只覆盖**未接管、未配置住宅代理**这一种状态，加上亮色、暗色两套主题。以下内容没有实机看到：接管中、需要恢复、UDP 阻断；状态岛展开；托盘菜单；应用窗口；升级流程。这些相关的条目只能靠读代码判断。
> - 每条后面标了证据等级：**实机**（截图里看得到）、**代码确定**（从代码能直接推出）、**推算**（按尺寸或组件源码推出，需要实机确认）。

## 结论

**界面整体干净统一，上一轮（11-23）的 21 条里 18 条已修好，3 条修了一部分。现在最大的问题在「提醒到位」：失败大体能看到，成功大多看不到；最危险的状态（需要恢复、可能直连）在窗口隐藏时几乎没人会发现。**

最要紧的五件事，前四件都是小改动：

1. **操作成功后大多没有任何提示**（第 1 条）。例如启动接管后「目标时区已改为 X 并已重启目标」，规范要求显示，实际看不到。
2. **预检失败显示的是英文内部码**（第 2 条），例如 `tooling.iptables_legacy_missing_or_unsuitable`。提示还让用户「查看阻断项」，界面上并没有这个地方。
3. **后台没在运行时，提示是一句空话**（第 3 条）：「操作失败，请检查当前状态后重试。」用户不知道该点「重新连接」。
4. **「需要恢复」的原因在首页被截成一行，没有悬停提示**（第 4 条）。「新连接可能直连，请停止接管」这半句正好被截掉。
5. **程序完全不发 Windows 系统通知**（第 5 条）。主窗口藏在托盘里、状态岛被关掉或者正在全屏时，接管失效只表现为托盘图标变红。这条要负责人定通知策略。

**建议顺序：**
- 先做第 1–4 条和第 6、7 条，都只改桌面端，不动后台协议。
- 第 5 条先定策略再做。
- 「美观」和「便捷」两部分大多是低风险的小改，可以排在后面成批处理。
- 第五节列了需要拍板的事。

## 一、提醒到位

### 1. 操作成功后大多没有提示【高｜代码确定】

- **原因**：所有操作结果都写进同一个提示字段 `notice`。界面只在出错时把它画成顶部错误条（`views.rs:466-469`）；除此之外，只有进度框正文会显示它，进度框一关就看不到了。
- **只写了 `notice`、哪里都不显示的成功结果**：
  - 启动接管：时区已改、目标已重启（`bootstrap.rs:1470-1482`）。只有 UDP 被阻断时才会弹提醒。
  - 放弃本次记录：「下次启动接管前，请先执行一次 wsl --shutdown」这句（`bootstrap.rs:1333-1334`）。
  - 导出诊断（`bootstrap.rs:1329`），也不显示文件路径。
  - 重置 DNS 别名（`bootstrap.rs:1338`）。
  - 停止接管：没有专门的成功提示，只能看首页状态卡变了。
  - 开机自启、状态岛开关（`actions.rs:56-60`、`78-82`）。
- **会显示的**：保存规则和设置（右上角通知）、新增/编辑/删除环境和改时区（结果框）、备份（结果框）。
- **建议**：用户主动发起的修改类操作，成功时一律推一条提醒通知（`reminder`，不标警告，5 秒后自动消失）。放弃本次记录那条标成警告，不自动消失。

### 2. 预检失败显示内部阻断码，还让用户去看不存在的列表【高｜代码确定】

- `bootstrap.rs:1286` 直接拼接：`预检未通过：{blockers.join("；")}`。阻断码来自 `src/probe.rs`，例如 `host_port_unavailable`、`permission.root_required`、`network.default_ipv4_gateway_ambiguous_or_absent`。桌面端只翻译了内核版本这一项（`backend.rs:445`）。
- `bootstrap.rs:1466` 写的是「请查看阻断项」，`backend.rs:524` 写的是「请查看预检结果」。可是 `self.preflight` 存下来之后，没有任何视图读它。
- **用户看到的**：错误条里一串用点号连起来的英文码。端口被占用这种最常见的原因也认不出来。
- **建议**：建一张阻断码到中文的对照表，每条写原因和下一步，例如「Windows 入口端口 43531 被占用 → 到设置页「网络入口」换一个端口」。没收录的码显示成「未知检查项（码）」，并提示导出诊断。「请查看阻断项」这句要么删掉，要么真的做一个阻断项列表。

### 3. 后台没在运行时，提示退化成一句空话【高｜代码确定】

- 后台进程不在时，IPC 报 `ipc_unavailable: Windows error 2`。`humanize_code`（`backend.rs:229-241`）没有这一类，最后落到兜底文案「操作失败，请检查当前状态后重试。」（`backend.rs:436`）。右上角通知因此显示「刷新状态失败：操作失败，请检查当前状态后重试。」
- 所有没收录的英文错误也都变成这一句，原始原因全部丢失。
- **建议**：
  - Windows error 2 映射成「后台没有在运行，点首页「重新连接」重新拉起」。
  - 兜底文案带上原始码，例如「操作失败（错误码 xxx），可到连接页导出诊断」，不要把信息全部吞掉。

### 4. 「需要恢复」的原因被截成一行，没有悬停提示【高｜截断和缺悬停为代码确定，截到哪里为推算】

- 首页说明行是 `div().text_color(MUTED).truncate().child(summary)`（`overview.rs:98`），没有悬停提示。
- 原因句由 `recovery_reason`（`overview.rs:976-1014`）生成，常见 80–150 个字。说明行大约只放得下 57 个汉字，后半句「若目标里有容器，它们可能直连。请停止接管并恢复直连」会被截掉，而且是灰色字。
- 「最近一次转发错误」（`overview.rs:113-119`）同样截断、没有悬停；连接页的同一条错误（`diagnostics.rs:813-827`）倒是有悬停，两处不一致。
- 状态岛的卡片在需要恢复时只显示发行版名，不显示原因（`island/model.rs:419-431`）。
- **建议**：
  - 需要恢复时，首页说明行改成可以换行的红色提示块，结论放句首，例如「新连接可能直连：……」；「停止接管并恢复直连」作为主按钮已经在右边，正文不必重复。
  - 状态岛卡片带一条短原因，例如「规则已失效 · 已断网」或「断网失败，可能直连」。

### 5. 程序不发系统通知；窗口隐藏时，危险状态几乎没人看到【高｜代码确定；能不能被注意到需实测】

- 全仓没有托盘气泡（`NIF_INFO`）、Toast 或任务栏闪烁（`FlashWindow`）。
- 接管中掉进「需要恢复」时，`accept_status`（`bootstrap.rs:1582-1626`）只更新状态，不比较前后阶段，不产生任何提醒。现有的提醒只有四个来源（`bootstrap.rs:1141/1215/1485/1525`），都和恢复无关。
- 这时用户能看到的信号只有：
  - 主窗口打开时：底栏盾牌图标变红。用户在日志、设置等页时只有这一处。
  - 状态岛：展开 10 秒，不带原因（`island/model.rs:494-524`）。岛可以被关掉；有全屏程序时岛会隐藏，但倒计时照走（`island.rs:371-379`），10 秒后就没了。
  - 托盘图标：由绿变红。Windows 默认会把托盘图标收进溢出区。
- 运行中新出现的 UDP 阻断、TCP 连接数满、DNS 别名号段用完，只出现在首页和连接页的「最近转发错误」横条里，也不产生提醒。
- **建议**（细节见第五节第 1 项）：
  - 进入需要恢复、后台失联超过一段时间、升级失败这三类，发一条 Windows 通知，同一原因只发一次。
  - 主窗口同时推一条不自动消失的警告提醒，正文用 `recovery_reason`。

### 6. 「操作后无法确认状态」会覆盖操作本身的失败原因【中｜代码确定】

- `bootstrap.rs:950-955`：先用真正的失败原因调用 `fail()`，紧接着再用「操作后无法确认状态…请刷新」调用一次 `fail()`，把前一条覆盖掉。
- WSL 升级的结果框读的是这时的 `notice`。所以升级本身成功、只是状态没读到时，结果框标题会写「WSL 升级失败」（`bootstrap.rs:958-966`）。
- **建议**：状态错误拼在原消息后面，不替换原消息。结果框的成败只看 `result_succeeded`。

### 7. 提醒通知只有一个位置，警告会被普通提醒顶掉【中｜顶替为代码确定，撞上的频率为推算】

- `bootstrap.rs:71` 在推新提醒前撤掉旧的。
- 不自动消失的警告有 UDP 已阻断、目标已自动清除、关窗期间后台在跑环境任务。它们可能被「发现新版本」「已是最新版本」这类 5 秒后自动消失的提醒顶掉，之后再也找不回来。
- 状态岛上也有同类问题（`island/model.rs:451-457`、`island.rs:631`、`794`）：
  - 警告提醒没有警告样式，接管中弹出的 UDP 警告仍然是绿色对勾。
  - 正文最多两行。UDP 警告的文案又是先写时区再写 UDP，真正的警告内容会被截掉。
- **建议**：
  - 警告和普通提醒分成两个通知编号，或者规定普通提醒不能顶掉正在显示的警告。
  - 状态岛记住提醒是不是警告，并给岛单独写短文案，例如「UDP 已阻断（TCP、DNS 照常经代理）」。

### 8. 长操作的进度框不说在做什么，也没有已用时间【中｜代码确定】

- 启动、停止、备份、复核出口、保存、准备内核这些操作，进度框标题都是「正在处理」（`views.rs:676-687`）。只有新增和编辑环境有阶段、百分比和已用时间。
- 启动接管要查时区、改时区、重启目标、再预检，通常一两分钟。WSL 升级最长 30 分钟。备份大发行版可能要很多分钟。这些期间进度框的正文都不变。
- **建议**：所有进度框都显示已用时间，可以直接复用新增环境的那套计时。标题写具体动作。启动接管至少分出「查询住宅出口时区 / 重启目标 / 验证接管」几个阶段，这需要后台配合报告进度。

### 9. 只读操作会锁住整个界面，包括「停止接管」【中｜代码确定；最长挂住时间为推算】

- `locked()` 包含「读取中」（`actions.rs:133-135`）。查看环境详情、刷新列表、连接后台、预检、导出都算读取，每次都会弹出模态进度框（`bootstrap.rs:795-801`）。
- IPC 的应答超时是 240 秒（`src/ipc/windows.rs:53`）。一次读取卡住时，首页的「停止接管」和托盘的停止都是灰的，想紧急停也停不了。
- 环境列表里点任意一行，都会在那个发行版里跑检查脚本，拉起没在运行的发行版，并弹模态框。规范第 205 行有意这么设计，所以要改规范，见第五节。
- **建议**：读取环境详情改成在右栏里显示「读取中」占位，不弹模态框、不锁界面。至少让「停止接管」不受 `locked()` 影响。

### 10. 接管期间能点删除、编辑、备份、改时区、新增环境，确认之后才被拒绝【中｜代码确定】

- 这几个按钮只按 `locked` 置灰（`views.rs:1431-1468`），由后台的 `require_idle` 拒绝（`src/desktop_control.rs:281-294`）。
- 被拒后的文案前缀有误导：「环境创建失败，组件安装未完成：…」（`bootstrap.rs:1034-1040`），其实什么都还没开始。而且同一个失败在结果框和错误条里各显示一次。
- **建议**：接管中把这些按钮置灰，悬停提示写「先停止接管并恢复直连」。被后台拒绝时去掉「组件安装未完成」这类前缀，结果框和错误条只留一处。

### 11. 其他提醒问题【中低｜代码确定】

- **删除环境的确认框没把后果说透**（`actions.rs:1407-1409`）：没写不可恢复，没建议先备份；删的是当前接管目标时，也没提目标会被自动清空。
- **导出诊断的路径会被备份路径顶掉**（`bootstrap.rs:1400`）：备份成功后，连接页的「打开报告位置」打开的是备份目录。
- **备份失败要重新填路径**：表单一提交就关了，失败只进错误条；再打开表单时路径被清空（`actions.rs:1352`）。
- **托盘退出不检查未保存的修改**（`actions.rs:693-735`）：规则页、设置页没保存的输入，退出时会悄悄丢掉。
- **保存成功的文案不分场景**（`drafts.rs:36-42`）：不管是否在接管，一律写「不会立即改变当前接管」。没在接管时应写「下次启动接管时生效」。
- **还没读的错误条会被非操作清掉**：打开新增环境表单、取消编辑、切换开机自启，都会把错误条清掉（`actions.rs:1068`、`1437`、`61`、`83`）。
- **「有新版本」在窗口隐藏时等于没发**（`update.rs:254-262`）：只提醒一次，5 秒后消失；托盘菜单和状态岛收起时都没有新版本标记。
- **一键升级会有一两分钟什么都看不到**：安装助手不显示窗口（`update.rs:1037`），托盘图标、状态岛、主窗口同时消失，用户容易以为程序崩了，再去打开程序，反而会让安装器拒绝这次升级。
- **应用窗口启动过一次应用后，「直连上网」的警告就不再显示**（`launcher.rs:454-459`）：从非接管环境启动 Chrome 后，提示变成「已启动 Chrome」，用户可能以为浏览器在走代理。
- **「后台状态未确认」在不同位置用不同颜色**：底栏是灰色（`views.rs:413`），首页是红色（`overview.rs:131-142`），托盘是琥珀色（`tray.rs:638`）。灰色看起来像「没在工作，很安全」，但这时接管可能仍在生效。
- **托盘图标只靠颜色区分「接管中」和「需要恢复」**（`tray.rs:635-643`）：两者都画心电波形，只有盾牌颜色不同，红绿色弱的用户在 16px 下分不出。状态岛已经用了对勾、感叹号两种不同图形，托盘没有。

## 二、文案和术语

### 12. 提示里有内部码、行话和不存在的名字【中｜代码确定，部分为实机】

- **错误前缀让翻译失效**：`actions.rs:64` 写的是 `fail(format!("开机自启设置失败：{error}"))`，而 `humanize_detail` 看到中文就原样返回，结果是「开机自启设置失败：autostart_write_failed:拒绝访问。 (os error 5)」。状态岛开关（`actions.rs:87`）、不透明度（`actions.rs:103`）、升级（`update.rs:240`、`294`、`707-716`）是同一种写法。
- **提示里引用不存在的按钮或页面**：「请用「退出接管」」（`backend.rs:358`），界面上叫「停止接管」；「概览页」「在总览」（`backend.rs:362`、`523`），侧栏叫「首页」；「请稍后手动预检」（`backend.rs:519`），界面没有手动预检的入口。
- **「请先刷新」没有对应的按钮**：出现在 8 处（如 `actions.rs:401`、`bootstrap.rs:927`、`overview.rs:178`）。真正能用的是首页「重新连接」或底栏的后台图标；环境页的「刷新列表」不会刷新后台状态。
- **术语不统一**：
  - 停止：「停止并恢复」「停止接管」「停止并恢复直连」三种说法。
  - 出口检测：「复核公网出口」「检测出口」「检测公网出口」。
  - 对象：「目标 WSL」「发行版」「环境」「目标」混用。
  - 其他：「新增环境」和「新建环境」；「接管」和「保护」。
- **普通用户看不懂的行话**（实机）：
  - 首页事件时间线「空闲 · 代次 287」。
  - 日志来源列显示 `runtime`、`lifecycle`、`desktop_store`。
  - 设置「桌面运行」页最后两行是「配置状态 待初始化」「Revision 0」。
  - 环境详情右上角的「未分配」，意思其实是「不是接管目标」。
  - 准备内核的确认框写 xt_cgroup、filter/nat 表、systemd oneshot（`actions.rs:482`）。
  - 停止确认框写「只清理本控制器的规则」（`actions.rs:422`）。
- **建议**：
  - 定一张词表，全局统一：接管、停止接管并恢复直连、检测公网出口、环境（指 WSL 发行版）。
  - 错误统一先翻译再加前缀。
  - 技术细节放进悬停提示或折叠详情，主文案用大白话。
  - 「Revision」「配置状态」挪进「关于」或者删掉。

## 三、操作便捷

### 13. 首次使用要跳三个页面，首页只告诉你缺一半【中｜实机】

- 全新配置启动后（`shots\m01-home-p.png`），首页说明行只写「还没有设定目标 WSL」，按钮是「去选择目标」。可同一张卡片的链路节点里，「住宅出口」也显示黄色「未配置」，却没有入口直达设置页。
- 完整路径大约 6 次点击、3 次换页：设置页填住宅代理并保存 → 环境页设为目标并确认 → 回首页启动接管并确认。设目标成功后的通知只写「接管目标已保存；不会立即改变当前接管」，不提示下一步。
- **建议**：
  - 首页在未就绪时列出缺的每一项，每项带跳转，例如「① 设置住宅代理 ② 选择目标环境」。
  - 设目标成功且一切就绪时，通知里直接给「启动接管」按钮。
  - 空闲时设目标是可逆的、代价很低的操作，可以不弹确认框（规范如此，见第五节）。

### 14. 好几处输入要么丢失，要么得来回切换【低｜代码确定】

- 住宅代理「检测」遇到未保存修改直接拒绝，提示「请先保存设置」（`actions.rs:640-645`）。可以改成「保存并检测」，一步完成。
- 新增环境表单：
  - 安装目录没有默认值（`actions.rs:1038-1070`）。
  - 校验错误进顶部错误条，一次只报一条，也不标出是哪个输入框。
  - 点「取消」不确认，填好的内容直接丢掉（`actions.rs:1433-1439`）。
- 整个程序不能复制任何文字，`desktop/src` 下没有任何剪贴板调用。错误原因、日志、公网出口 IP、安装路径、配置库路径都只能手抄或截图。
- 没有任何键盘快捷键：没有 Ctrl+S 保存、没有 Ctrl+F 搜日志；备份框和时区框按回车不提交（`views.rs:786`、`954`）。
- **建议**：检测改成「保存并检测」；新增环境的错误标到对应输入框，有内容时取消要先确认；错误条、日志行、地址和路径旁边加复制按钮；加 Ctrl+S 和 Ctrl+F。

### 15. 按钮被禁用时不说原因【低｜实机】

- 打开新增环境表单后，左栏四个「设为目标」全部变灰（`shots\m14-env-new.png`），「新增环境」「刷新列表」也变灰，都没有任何说明。
- **建议**：禁用的按钮加悬停提示说明原因，例如「先保存或取消右侧表单」。

### 16. 托盘、状态岛、应用窗口【中低｜代码确定】

- **开机自启每次都把主窗口弹到前台**：注册表只写了 EXE 路径，没有参数（`autostart.rs:29-31`），每次开机都要手动关一次窗口。可以加一个 `--tray` 参数，自启时直接藏到托盘。
- **状态岛一碰就展开**：光标进入就展开成约 380×230 的置顶卡片，没有停留判定（`island/model.rs:481-483`）。浏览器最大化时，往屏幕顶部中间点标签页很容易误触。卡片空白处还会吃掉点击。可以加 250–400ms 的停留判定再展开。
- **托盘和状态岛上的按钮都要先叫出主窗口**（`island.rs:285-290`、`tray.rs:477-480`）：需要恢复时「停止并恢复直连」至少点两次，中间还要等主窗口跳出来。这是设计文档定的，见第五节。
- **应用窗口**：没有搜索；格子不能用键盘聚焦或按回车启动（`launcher.rs:394-398`）；入口只有环境详情右上角一个图标。
- **单实例**：第一个实例以管理员身份运行时，再双击快捷方式，显示窗口的消息会被 Windows 的权限隔离拦下，第二个进程静默退出（`tray.rs:312`、`instance.rs:25`）。

## 四、界面美观

总体评价：**亮色和暗色两套主题都干净、统一，颜色全部走主题变量，没有写死的颜色。**问题主要是信息层级弱、空间分配不均，以及一些截断（`shots\m*.png` 是暗色，`shots\l*.png` 是亮色）。

### 17. 最重要的状态和普通文字一样大【中｜实机】

- 首页的「未接管 / 接管中 / 需要恢复」和下面的灰色说明同样是 12px、常规字重，只靠颜色区分。远看时，或者色弱用户，很难一眼看出现在安不安全。
- 这是规范「所有文字 12px、只有应用标题加粗」带来的结果，见第五节。

### 18. 空间分配不均【低｜实机】

- **首页空闲时下半屏全空**（`m01-home-p.png`、`l03-home.png`）：流量卡只有一句空态，却占着整张卡。空闲时可以把空间留给「启动前还差什么」的清单（见第 13 条），或者整体缩短。
- **环境页左右两栏底边不齐**（`m13-env-detail.png`）：左栏卡片到窗口底部，右栏详情卡在约 610px 处结束，下面是一大块空白。
- **规则页三个输入框等宽**（`m03-rules.png`）：「域名后缀」默认有几十条，另外两个是空的。框里没有条数统计，也看不出哪一行格式不对。

### 19. 截断后看不到全文【中｜实机加代码确定】

- 实机看到的：
  - 环境详情的内核「6.18.58.1-microsoft...」（`m13-env-detail.png`）；
  - WSL 平台页「权限：标准用户（升级时可能要确认管理…」（`m08-wslplat.png`）。
- 代码里截断且没有悬停的还有：日志行的消息和上下文（`views.rs:1822-1823`）、首页事件时间线（`overview.rs:784-790`）、通用的键值行（`views.rs:94-117`，用于 wsl.exe 路径、上次升级结果、住宅检测结果）、安装位置（`views.rs:1511-1518`）。
- 首页链路节点里的「出口已核对 · UDP 已阻断」大约 141px，节点文字宽约 136px，最后两个字可能被切掉（推算）。
- 规范第 382 行要求截断的文字能悬停看全文。**建议**：做一个带悬停的截断文本组件，把所有 `.truncate()` 都换成它；日志行另外加悬停看全文或点开看详情。

### 20. 操作按钮的摆放【低｜实机】

- **环境详情右上角五个纯图标按钮**（`m13-env-detail.png`）：刷新、应用、编辑、备份、删除，没有文字。红色的删除紧挨着备份。其中「编辑」比其他四个小一号（`views.rs:1443` 单独加了 `.small()`）。建议删除和其他按钮隔开，或者收进「更多」菜单。
- **连接页顶部四个按钮**（`m04-conn.png`）：「复核公网出口 / 导出脱敏诊断 / 重置 DNS 别名 / 打开报告位置」挤在页面右上角，不属于任何卡片，功能彼此无关。「重置 DNS 别名」普通用户不知道什么时候该点。建议「复核公网出口」放进「公网出口」卡片；「导出诊断」和「打开报告位置」合并成一个按钮；「重置 DNS 别名」挪到设置页的 DNS 分组。
- **WSL 平台页**（`m08-wslplat.png`）：状态「正常」时，「升级 WSL」仍然是绿色主按钮，最醒目。而升级会重启 WSL，正在运行的程序都会停止。没有新版本时应改成普通按钮。
- **新增环境表单**（`m14-env-new.png`）：安装目录的占位符写「Windows 绝对目录，例如 D:\WSL\Ubuntu-Dev」，下面的说明却是「选择父目录，系统会自动创建环境名称子目录」，两句话互相矛盾。「创建并设置」按钮在卡片最底部，离最后一个输入框隔着一大段空白。

### 21. 其他视觉细节【低】

- **「设置 › 桌面运行」的不透明度滑块拖动后，主窗口没有变化**（`actions.rs:95-105`）：它只影响状态岛和应用窗口。标签应改成「状态岛和应用窗口的不透明度」。（代码确定）
- **状态岛在 50% 不透明时**，暗色岛压在白色网页上，次要文字（本身也带透明度，`island.rs:83`）对比度大约只有 2:1；而 `opacity.rs` 开头的注释说「调得再低也看得清」。浅色岛压在白色背景上几乎看不出轮廓。（推算，需要在接管状态下截图）
- **字体**：代码指定了 `Inter` 和 `IBM Plex Mono`，但两种都不打包（`theme.rs:52-53`）。实机截图里中文和数字都靠系统回退显示，看起来正常；等宽列在其他机器上能否对齐，取决于那台机器有什么字体。（实机加代码确定）
- **日志和连接页的筛选按钮**：选中时底色只比悬停深一点（gpui-component 的描边按钮默认行为），在暗色主题下看得出来，但不明显（`m04-conn.png`、`m05-logs.png`）。建议选中项改用 `accent-soft` 底、`accent` 字。

## 五、需要负责人拍板的事

1. **要不要加 Windows 系统通知（第 5 条）。** 建议加，范围先限在三类：进入需要恢复、后台失联超过 30 秒、升级失败。同一原因只发一次，设置里给一个开关。
2. **「后台状态未确认」统一用什么颜色（第 11 条）。** 规范第 149 行（底栏灰色）、第 177 行（首页红色）、第 362 行（托盘琥珀色）互相矛盾。建议统一成琥珀色，因为这时接管可能还在生效。
3. **「所有文字 12px、只有标题加粗」这条规则（第 17 条）。** 建议正文保留这条，但首页那一句保护状态允许大一号或者用中等字重。
4. **点环境行就在发行版里跑检查、拉起发行版，还弹模态框（第 9 条，规范第 205 行）。** 建议列表只显示已有的信息；读取详情改成不弹遮罩，或者改成显式的「读取详情」按钮。
5. **托盘和状态岛上的「停止」要不要不开主窗口直接执行（第 16 条）。** 建议只给「停止并恢复直连」开这个口子，在岛上或托盘气泡里原地二次确认。其他操作保持现状。
6. **空闲时「设为目标」要不要免确认（第 13 条，规范如此）。** 建议空闲时直接保存，只在接管中弹框说明「下次启动才生效」。
7. **开机自启要不要直接藏到托盘（第 16 条）。** 建议要。
8. **固定 980×700 的窗口在 1080p 屏、150% 缩放的笔记本上放不下。** 这时可用高度约 672px，窗口底部会被任务栏挡住（推算）。是保持固定，还是允许把高度缩到大约 620px？
9. **规范缺了这批新功能。** `design/ui-design-spec.md` 里没有状态岛、检查更新、已安装应用、不透明度；托盘菜单清单少了「显示顶部状态岛」；第 396 行「空闲时托盘退出直接关闭」和 13d3e0f 加的退出确认矛盾。要不要一次补齐？
