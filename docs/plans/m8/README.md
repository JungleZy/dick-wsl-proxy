# M8 · 检查更新与一键升级

**结论：桌面端能查到 GitHub 上的新版本、提醒一次，并在用户确认后下载、核对安装包，交给包里的 `install.ps1` 升级。** 设计见[讨论记录](../../discussions/2026-11-25-设计方案-检查更新与一键升级.md)和[决策 31](../../decisions.md)。0.1.11 及更早的版本没有这个功能，0.1.12 是第一个带它的发布版本。

## 操作边界

| 会做 | 不会做 |
|---|---|
| 打开程序 15 秒后、之后每 24 小时查一次 GitHub 的发布列表（「自动检查更新」缺省开，记在 `HKCU\Software\WSLProxyLab` 的 `UpdateCheck`，0 为关）；「检查更新」随时手动查。 | 不静默下载、不静默安装；不降级。 |
| 只认 `vX.Y.Z` 标签、非草稿、ZIP 与 `.sha256` 都在 `github.com/JungleZy/dick-wsl-proxy/releases/download/<tag>/` 下的发布，取版本号最大且比当前新的那个；预发布照样算。 | 不认别的仓库、别的地址或带后缀的标签（`v0.2.0-rc1`）。 |
| 经已保存的宿主 SOCKS5（免认证，按域名 CONNECT）访问，连不上再直连；跳转只跟到 `github.com`、`api.github.com` 和 `*.githubusercontent.com`。 | 不经住宅代理；不用输入框里还没保存的宿主 SOCKS5。 |
| 下载在桌面进程里边写盘边算 SHA-256，大小和发布页列的一致、摘要和 `.sha256` 一致才算完成；同一版本已核对过的包不重复下载。 | 不经后台下载或安装；不验证签名或构建来源证明（包没有签名）。 |
| 一键升级前确认：后台状态已确认、空闲、没有接管目标、没有其他操作；EXE 旁边有安装记录且目录一致；没有未完成的安装事务；PowerShell 当前生效的执行策略是 RemoteSigned、Unrestricted 或 Bypass。 | 不改执行策略，不加 `-ExecutionPolicy Bypass`；不替用户停止接管；不提权。 |
| 拉起独立的 PowerShell 进程（无窗口，尽量脱离桌面所在的作业，工作目录在 `%LocalAppData%\WSLProxyLab\updates`），桌面随即退出。那个进程等桌面退出（最多 2 分钟）、再核对一次摘要、解压到 `updates\<版本>\package`、核对 `release.json` 的版本，运行 `install.ps1 -InstallDir <安装记录里的目录>`，把结果写进 `updates\result.json`，再重新打开桌面。 | 不结束任何进程；安装器的检查、事务、回滚一个不跳。 |
| 安装器成功：删掉 `updates\<版本>`；新桌面打开后提示「已从 vA 升级到 vB」并清掉 `updates`。桌面除了启动时读结果文件，运行中每 5 秒也看一次：升级期间用户自己打开了程序时，安装器会拒绝（窗口开着），助手只能唤醒这个窗口，它靠轮询显示结果。确认框和 README 写明窗口关闭后通常要一两分钟才重新打开、期间不要自己打开。安装器拒绝或没走到安装器：重新打开桌面，结果框给出原因、安装器输出的最后 12 行，以及包还在时可手动运行的命令。文件替换中断（安装器留下事务记录）：不重新打开桌面，弹窗给出 `-Recover` 命令。 | 中断时不自动重试、不自动恢复。 |

## 文件

| 位置 | 内容 |
|---|---|
| `src/update.rs`、`src/update/tests.rs` | 库里的平台无关部分：版本、发布挑选、SOCKS5、HTTP/1.1（跳转、分块、长度上限）、下载与核对 |
| `desktop/src/app/update.rs`、`desktop/src/app/update/tests.rs` | 桌面端：检查时机、开关、升级前的判断、执行策略、确认框、安装器助手脚本、结果显示 |
| `desktop/src/app/views.rs` | 「设置 › 关于」的「更新」一组；状态栏「有新版本」 |

「自动检查更新」的注册表值和主题设置一样，卸载时不删。

## 验证（2026-11-25，Windows 11 本机，标准用户，执行策略 RemoteSigned）

- `cargo fmt --all --check`、`cargo clippy --locked --workspace --all-targets -- -D warnings` 无告警；`cargo test --locked --workspace`：控制器 268 项、库 29 项（新增 `update` 18 项，另有 1 项手动运行的联网测试）、桌面 72 项（新增 14 项，另有 1 项手动运行的 `qa_hand_off`）通过。桌面的一项测试让本机 Windows PowerShell 解析生成的安装器助手脚本：解码后长度与原文一致，0 个语法错误。
- 联网测试（`update::tests::live_check_and_download`，手动运行）：直连和只经本机宿主 SOCKS5（`127.0.0.1:7892`，不留直连兜底）各跑一次，都从 GitHub 发布列表选出 v0.1.11，跟随跳转下载 43,189,826 字节，SHA-256 与发布页的 `.sha256` 一致；再调用一次直接复用已核对的包，不重复下载。
- 界面全流程（QA 目录 `D:\WSL\ProxyLab\update-qa`，权限收紧的私有父目录；版本号临时改成 0.1.10 和 0.1.12 各打一个本地包，用 0.1.10 的 `install.ps1` 装好后启动它的桌面）：
  - 打开 15 秒后自动检查，状态栏出现「有新版本 v0.1.11」；点它跳到设置页。「设置 › 关于 › 更新」显示「有新版本 / 1 分钟前检查」、当前 v0.1.10、新版本 v0.1.11（2026-11-25 发布）、安装包 41.2 MB，「升级到 v0.1.11」可点。
  - 点升级：读到执行策略 RemoteSigned，弹出确认框（安装包名、大小、经宿主 SOCKS5 访问、安装目录、后台须空闲、没有签名）。确认后约 6 秒下载并核对完，窗口关闭，26 秒后重新打开。
  - 这次升级被官方 0.1.11 的安装器拒绝：QA 的 0.1.10 包来自当前代码，带 `LICENSE`，旧安装器不认识（`Unexpected package filename: LICENSE`）。程序文件和后台都没动；重新打开的 0.1.10 弹出「升级没有完成」，说明原因、给出手动运行的命令和安装器原文。这只发生在 QA 的人造版本上：真实用户是从不带 `LICENSE` 的 0.1.11 往更新的包升级。
- 成功路径（`desktop/src/app/update/tests.rs` 的 `qa_hand_off`，手动运行，和桌面用同一份助手脚本与启动方式，只是不经界面、不下载）：把本地 0.1.12 包交给 QA 里的 0.1.10。助手核对、解压、运行新包安装器；安装器关掉空闲后台、完成替换，结果 `installed`，用时约 75 秒；重新打开的桌面提示「已从 v0.1.10 升级到 v0.1.12」，状态栏 v0.1.12，原来的运行日志保留，`updates` 目录被清掉。之后它自动检查显示「已是最新」，升级按钮置灰；手动「检查更新」提示「已是最新版本（v0.1.12）」；「自动检查更新」开关在注册表里写 0 / 1。
- 中断分支：在 QA 安装目录旁放一个假的事务记录再交接，安装器拒绝并保留记录，结果 `interrupted`，助手不重新打开桌面，弹出系统消息框，给出 `& '…\updates\0.1.12\package\install.ps1' -InstallDir '…' -Recover`。
- 测完用 0.1.12 的 `uninstall.ps1` 卸载 QA 安装（它的输出没有看到），随后直接删除了整个 QA 安装目录、`updates` 目录和测试写入的 `UpdateCheck` 值；没有残留进程。截图和 QA 脚本在 0.1.12 发布前随 QA 目录一起删除，没有保留。
- 合并 main 的托盘改动（`cfa17de`）后，在合并提交 `fe55821` 上重新跑了第一条的三个命令：控制器 268 项、库 29 项、桌面 88 项（多出的 16 项是托盘的测试）通过。合并没有改动窗口关闭和退出的代码；界面流程、联网测试和 `qa_hand_off` 没有重跑。
- 0.1.12 发布后，在 Windows 上直连再跑一次联网测试（仍以 0.1.10 的身份检查）：选出 v0.1.12，下载 40,832,212 字节，SHA-256 与发布页的 `.sha256` 一致。

**未覆盖：**

- 从 GitHub 下载并**成功**升级的整条界面路径：下载和安装分开验证过（联网测试、`qa_hand_off`），没有连起来跑过。0.1.12 发布后已经可以在本机测：把当前代码的版本号临时改低、装进 QA 目录，让它从 GitHub 下载 0.1.12 并升级（0.1.12 的安装器认识 `LICENSE`），这一步还没做。真实用户第一次走这条路径，要等 0.1.12 之后再发一个版本。
- 执行策略为 Restricted / AllSigned 时的拒绝提示、非安装器副本的提示、接管中按钮置灰，只有单元测试，没在界面上实测。
- 真正的文件替换中途中断（安装器移动目录到一半）没有模拟，只用假事务记录走了同一个分支。
- 限流（HTTP 403/429）只有单元测试。
- 升级期间用户自己打开程序：靠运行中每 5 秒读一次结果文件来显示安装器的拒绝，这条没有实测。
- 以管理员身份运行的桌面或后台都没有测过。桌面以管理员身份运行时，助手和安装器也以管理员身份运行，而安装包放在当前用户可写的 `%LocalAppData%\WSLProxyLab\updates` 里；助手解压前会再核对一次 SHA-256，但核对之后到解压之间，同一账户的普通权限进程仍可能改动这个目录。是否要为此在管理员身份下拒绝一键升级，留给负责人决定。
