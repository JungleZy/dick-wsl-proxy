# M4：Windows GPUI 控制台

## 运行方式

将 `wsl-proxy-desktop.exe` 与同版本的 `wsl-proxyctl.exe` 放在同一个目录，运行桌面 EXE。窗口是 GPUI 原生渲染，不是浏览器页面。首次连接会以当前用户身份启动配套控制器的 `daemon` 模式；整个 UI 不需要以 Windows 管理员身份运行。

1. 在**总览**选择候选发行版和 Windows 业务入口端口。只选中目标不会接管网络。可先运行只读预检；失败时处理显示的能力缺项，程序不自行安装 WSL 软件。
2. 在**策略**填写宿主机已有 SOCKS5 入口、住宅凭据名称、DoH 上游的字面 IPv4:端口与 TLS 名称、健康检测域名及直连白名单。第一次建配置库时 DoH 上游预填 Google DoH（`8.8.8.8:443`、`dns.google`）；早先预填的 AliDNS 是 M3 的实验值，国内解析商会让权威端重新看到国内递归，与接管系统 DNS 的目的相反。第一次建配置库时，规则页的「域名后缀」还会预填一批国内常用服务的后缀（不超过 100 条，由单测保证；百度、腾讯、阿里、京东、B 站、国内云与软件源、国内大模型等，清单在 `src/policy/domestic.rs`），IP / CIDR 和精确域名两列仍为空；不含裸 `cn`，要让全部 `.cn` 直连就自己加一行 `cn`。这些后缀和手填的一样：只决定连接是否直连，DNS 查询照旧经双跳问 DoH 上游；命中的每个「域名 + IP」组合都会占用一个 DNS 别名，用尽时按连接页「重置 DNS 别名」处理；目标启用受管 IPv6 时任何域名规则都会让启动被拒（`ipv6_domain_allowlist_unsupported`），需先清空两列域名规则。已经存在的配置库保留原值，要换就在策略页改。导入 `.env` 是一次明确操作：文件路径交给当前用户的本地后台，用户名/密码不显示在编辑器中。保存草稿不会改变正在运行的链路。
3. **显式保存策略**，回到总览确认启动。确认切换才开始释放当前目标。若另一个窗口修改了策略或接管代次已经变化，陈旧操作会被拒绝，而不是重新发送。根据后台返回的实际状态决定是否继续。
4. **连接与诊断**显示实际转发的活跃/最近连接、原目标、命中策略、累计字节与采样速率。普通 UDP 不支持双跳时显示拒绝，不算直连。出口地址不是 SOCKS 节点参数或 HTTPS 的对端地址；只有显式点击“检测出口”才从实际受管发行版访问 IPPure，并记录观测时间。DNS 就绪是有时间戳的探测结果，不表示所有域名在此后都一定可用。
5. **关窗不是退出，托盘「退出」才会让后台一起退出。** 点窗口的关闭按钮只把窗口收进托盘，后台继续持有当前目标与规则，双击托盘图标可重新打开。托盘图标没能显示时（例如开机时 Explorer 还没就绪），点关闭按钮直接退出界面，后台照旧保留，免得窗口藏起来后找不回；托盘每秒重试一次图标，Explorer 重启后也会重新加上，图标出现后关窗恢复为收进托盘。托盘菜单的「退出」：后台空闲时直接关闭后台再退出程序；接管中或需要恢复时先弹确认，确认后停止接管并恢复直连、关闭后台，最后退出程序。停止没有完成，或后台拒绝关闭（例如还有环境操作在跑）时，程序不退出并提示原因；联系不上后台时，可以选择只退出界面，后台如果还在运行会保留。桌面进程被强制结束或崩溃时，后台照旧保留，重新打开可连接。后台在状态未知或需要恢复时不会因为 UI 退出而放行。无法从 GUI 停止时，用下述命令查询或恢复。（托盘退出连带关闭后台、托盘图标重试与无图标时关窗：代码已改，Windows 原生构建与单测通过，托盘相关流程尚未在 Windows 上实测。）

## 后台与故障边界

- `wsl-proxyctl.exe session` 仍是 CLI 自己持锁的前台模式，EOF 保留原有的正常停止语义。桌面使用独立的命名管道后台，两者不能同时拥有同一个用户的网络控制权。已有 CLI 会话时不要强杀它来启动桌面；先在原会话中正常停止并退出。
- 窗口与后台通过仅当前用户、本机可连接的命名管道交换有界 JSON。客户端在发送请求前核对服务端进程的用户和配套 EXE 身份。读写有时限，未确认的变更不会因窗口断连被自动重放。拿不到状态时应显示未知，并重新读取后台，而不是使用过期绿色状态。
- 关闭窗口后也能在同目录 PowerShell 调用：`'{"command":"status"}' | .\wsl-proxyctl.exe rpc`。要主动停止，将状态中的实际 `operation_generation` 带入 `{"command":"stop","expected_generation":…}`。正常恢复至 `idle` 后，发送 `{"command":"shutdown_daemon"}` 可退出后台，便于替换 EXE。不能带着活动规则退出后台；如果后台已崩溃，沿用 [M3 的独立恢复流程](../m3/README.md)，不手删恢复日志；目标已被注销时，用概览页「放弃本次记录」，之后执行一次 `wsl --shutdown`。
- EXE 所在目录带有 Windows「低完整性」强制标签时（例如被开发工具沙箱标记的工作目录），系统以 Low 级别启动其中的程序，双击时还会弹「无法验证发布者」的安全警告。Low 级别的后台打不开 LocalAppData 中的锁文件，托盘图标也无法注册，所以桌面 EXE 启动时一旦检测到自身低于普通用户级别，就弹框说明原因和所在目录，然后直接退出，不占用单实例锁。处理方法：将两件 EXE 一起复制到不带该标签的目录运行，或移除目录标签；不需要以管理员身份运行。
- 桌面草稿在 EXE 同级目录的 `desktop.sqlite`，含策略、选择、版本，以及住宅服务器与凭据（含密码，明文）。保存操作使用版本比较避免覆盖另一窗口的修改。脱敏诊断同样导出到 EXE 同级目录（`diagnostics-<时间>.json`），只保留状态与数值计数，不导出原始请求正文、目的地址、域名、凭据引用或任意错误全文。该库没有额外加密，依赖 Windows 账户的文件权限。
- 程序运行产生的其他文件也放在 EXE 同级目录：环境新建/编辑的进度文件 `environment-progress-<名称>.json`，以及和 `wsl.exe` 交换输入输出的临时文件 `io-*.tmp`（关闭即删）。EXE 所在目录必须可写，否则配置库和 WSL 调用都会失败，错误信息里带出该目录。
- 早先版本把 `desktop.sqlite` 放在当前用户 LocalAppData 的 `WSLProxyLab` 下。新版后台第一次打开配置库时，若 EXE 旁边还没有配置库，就把旧库（含未合并的 WAL 内容）整理复制过来，落盘后再删除旧文件；迁移失败直接报错并给出旧文件路径，不会换成空配置库继续。EXE 旁边已有配置库时不再迁移，也不覆盖。
- 以下文件仍按 Windows 账户放在 LocalAppData 的 `WSLProxyLab`，不跟程序文件夹走：控制锁 `controller.lock`、恢复记录 `m1-active.json` 与 `m3-operation.json`、DNS 别名账本 `dns-alias.*`。它们保证每个账户只有一个控制器，并且崩溃恢复和别名分配不会因为换了文件夹运行而丢失或被悄悄重置。主题偏好和开机自启在注册表 `HKCU`，住宅凭据在 `desktop.sqlite`，都不在 LocalAppData 下。
- 连接记录是有界的内存数据，不是抓包：最多 256 条活跃、128 条近期记录；近期保留 5 分钟。`tx`/`rx` 是入口实际处理的传输字节；速率是两次采样的增量，不是线路测速。无内核映射时不虚构目标或域名。

## 住宅代理检测

**设置页「住宅代理」分区的「检测」分组有一个「检测」按钮，告诉用户这台住宅代理能否从 Windows 直接连上、能否经宿主 SOCKS5 连上。** 它只是诊断：接管始终经宿主 SOCKS5，检测结果不改变路由。（代码已改；新探测的单测在 Windows 上跑过；按钮点击流程和真实住宅服务器都没有实测。）

- **用什么配置：** 只用配置库里已保存的住宅服务器、账号和宿主 SOCKS5。设置页有未保存修改时拒绝检测并提示先保存；检测之后设置又保存过，「检测」分组把旧结论标成「设置已改，需重新检测」，不再显示。
- **测什么：** 后台同时走两条路，每条最多 8 秒：
  - **直接连接**：Windows 直接连住宅服务器；
  - **经宿主 SOCKS5**：先经宿主 SOCKS5 再连住宅服务器。

  两条都完成 SOCKS5 用户名密码登录，再让住宅代理 CONNECT 到配置里的 DNS 上游（字面 IPv4，不需要本地解析）。连上即停，不发应用数据。
- **账号密码会直接发出去：** 直接连接那一路不经前置代理，SOCKS5 的用户名和密码是明文，会经本地网络发出，住宅服务商也会看到真实 IP。这是维护者选定的做法（只做方法协商、不登录的方案会误报），所以点「检测」后先弹确认框说明这一点，确认后才发请求。经宿主 SOCKS5 那一路和接管时一样，外层 CONNECT 成功前不发住宅认证。
- **结论：** 「检测」分组显示以下几种结论之一，并分别列出两条路停在哪一步：
  - 两条都通；
  - 需要宿主 SOCKS5；
  - 只能直连：接管会失败，因为接管始终经宿主 SOCKS5；
  - 登录被拒绝：两条都不通，且至少一条被拒在登录这一步；也可能是服务商只允许白名单里的来源 IP；
  - 都不通。
- **两条路分别停在哪一步：** 能停下的位置有：连不上宿主 SOCKS5、宿主拒绝握手、宿主连不到住宅服务器、连不上住宅服务器、住宅服务器不接受用户名密码方式、登录被拒、登录后连不到外部地址。
- **请求与日志：** 桌面端通过 RPC `{"command":"residential_probe"}` 发起检测，不锁界面，结果只写进「检测」分组。运行日志只记结论（来源 `residential`），不记地址和账号。
- **局限：** Windows 上开着 TUN 或全局模式的代理时，「直接连接」也可能被它接管，结果会显示能直连。检测在请求期间占用后台，状态刷新最多晚 8 秒左右。

## 按页保存（2026-11-23）

**结论：每页只保存本页的内容。** 规则页「保存规则」只存直连规则，设置页「保存设置」只存住宅代理、代理链、DNS、转发限制和 Windows 入口端口。环境页没有保存按钮，点「设为目标」确认后立即只存目标。后台接口没有改：每次保存仍发整份配置，其他页的字段用已保存的值。由负责人决定，审查讨论见 [UI 审查第 18 条](../../discussions/desktop-ui-review-48c3aa0.md)。

实现时另定了两条，尚未登记到 `decisions.md`：

- **首页不保存任何内容。** 有未保存修改时，首页主按钮是「去保存修改」，跳到有改动的那一页。启动接管的提示会写明是哪一页没保存。首页改成跳转是实现时的选择，待负责人确认。
- **失效的目标自动清除。** 连接后台、刷新列表或删除环境后，如果保存的目标发行版不在列表里或不再是 WSL 2，就自动保存一次空目标，并在提示里说明。判断规则和后台一致：名称相同，或 ID 不区分大小写相同。这一条由负责人决定。

另外两处同时修正：

- **住宅代理留空也能保存设置页。** 四项都空时按「还没配置」保存，后台本来就接受这种空记录；以前前端一律要求端口有效，没配住宅代理就改不了设置页的其他字段。已保存的空记录端口为 0，输入框显示为空。
- **重连只保留有改动的页。** 重连后台时，有未保存输入的页保留输入框，其余页和配置版本号换成后台最新的。以前只要有一页没保存，就整份不读，之后的保存会因为版本号过期被拒。

验证：Windows 原生构建、桌面单测和 clippy 通过。确认框、各页标签、自动清除的提示和重连保留输入还没有在窗口里实测。

## 构建

- 原生 Windows：准备 Rust 和 GPUI 所需的 Windows 构建工具，执行 `cargo build --locked --release -p wsl-proxyctl -p wsl-proxy-desktop`。两件产物位于同一 `target\release`。仓库默认 Cargo 成员仍是控制器，构建 CLI 无需编译 GPUI。
- WSL 交叉构建：使用 [隔离构建脚本](../../../scripts/build-desktop-windows.sh)，环境要求见 `--help`。脚本只修正临时 GPUI 源副本对宿主平台的编译开关，使用 Windows 自带的 Direct3D HLSL 编译器生成真实 shader 字节码，不修改 Cargo 注册表、仓库锁文件或 Windows 全局工具链。产物是 Windows x64 EXE；这不是安装包或已签名的发布渠道。
