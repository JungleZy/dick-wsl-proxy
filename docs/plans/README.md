# 首版开发计划：单个 WSL2 接管与切换

**状态：M5 的发布流水线已发布到 [0.1.12](https://github.com/JungleZy/dick-wsl-proxy/releases/tag/v0.1.12)（Windows x64，未签名的预发布包），M6 增加冷启动内核环境的显式准备，M7 增加 WSL 平台的只读检查与显式升级，M8 增加桌面端的检查更新与一键升级。** 安装、升级、卸载、恢复方法及验收边界见 [M5 发布记录](m5/README.md)。桌面与 CLI 共用单目标控制逻辑；M3 切换、M4 桌面操作、M5 发布流程、M6 内核准备和 M7 平台检查的实机证据分开记录。

本计划安排交付顺序，不把实验脚本算作产品实现。设计边界见[接管架构](../arch/README.md)、[决策登记](../decisions.md)和 [Rust + GPUI 实现方案](../discussions/2026-11-19-实现方案-Rust与GPUI接管指定WSL2发行版.md)。

## 第一项可演示的交付

先做无界面的 Windows Rust 控制器，而非配置窗口。用 D 盘两套实验发行版演示一个完整操作：接管 A，确认它的普通命令和已有服务的新连接可被识别；停掉 Windows 入口，受管新连接失败且不直连，B 仍可访问同一目标；主动停止，A 的新连接恢复原路。接收端的唯一请求标记、规则计数和恢复后的基线三者都要能对上。此时只是开发里程碑，DNS、真实出口及协议覆盖未过关前，不显示产品级“已接管”。

## 里程碑与完成条件

按 M0 至 M5 顺序验收。每阶段的右栏是进入下一阶段的条件，不以“进程启动了”或“界面按钮可点”代替。已有的[网络验证](../discussions/2026-11-19-验证记录-指定WSL2发行版接管.md)和[公网对照](../discussions/2026-11-19-公网诊断-Net.Coffee双发行版对照.md)提供基线，不替代 Rust 产品路径的回归。

| 阶段 | 开发任务与交付物 | 如何判定完成 |
|---|---|---|
| M0 · 目标识别与预检 | 完成发行版枚举、目标身份和网络模式识别、能力清单。定义实际目标、配置代次、运行状态和错误原因；Windows 后台持有每用户唯一控制锁。先记录 DNS、路由及与实验有关的规则基线。 | A/B 共享 IP、使用相同 UID 时仍不混淆。预检不落规则；无法证明 cgroup 边界、缺少权限或端口冲突时给出原因，不启动、不擅自安装依赖。第二个控制实例不能操作网络。 |
| M1 · 可逆的业务入口 | 在目标上下文安装有所有权标识的临时规则，Windows 核对连接跟踪的原始及回包元组，还原目的地址，再转发。完成无需 GPUI 的启动、状态、停止、故障恢复入口。先实现精确回滚，再扩大匹配范围。 | 完成上面的无界面演示；覆盖同端口不同目的地址、UDP 发完即关、重复停止、端口被占。映射缺失或有歧义就拒绝。旧 UDP 只清本实例映射，旧 TCP 排空或要求重连；不可通过清空共享表或重启 WSL 达成恢复。 |
| M2 · 双跳、白名单与默认 DNS | 在 Windows 复用宿主机已有代理入口，通过它连接住宅 SOCKS5，再认证并访问最终目标。实现 IP/CIDR、精确域名和后缀白名单、未命中走链、失败拒绝。同步接管目标系统 UDP/TCP 53，必要时仅为该 DNS 回程做源地址转换；指定上游的查询通过同一链路。凭据仅在 Windows 保管。 | 受控目标和真实住宅出口均验证；白名单业务直连但 DNS 不因此直连（这是 M2 当时的验收口径；[决策 18](../decisions.md) 起，白名单域名的 DNS 改由 Windows 直连国内 DoH 上游，失败回落双跳）。公网出口 IP 与首跳选路分别核实，不能以其中一项替代另一项。未缓存系统查询以权威端记录验收，含强制 TCP 查询和后台服务；分别断开首跳、住宅、DNS 上游和 Windows 入口，验证不会回落本地解析、直连或单跳。 |
| M3 · 单目标切换与异常恢复 | 把启停、切换和恢复串行化，记录目标身份、操作代次、自有规则、监听及待清理的映射。后台重启时重新识别实际归属，不凭上次 UI 状态恢复。 | 完整通过下节的 A/B 切换矩阵。切换任一步中断后，不会同时接管两者，不让旧回复修改新目标，不把“状态未知”报成“已停止”。 |
| M4 · GPUI 配置与监控 | 接入后台控制接口：发行版选择、启动/停止/切换、宿主代理端点与住宅凭据、白名单、DNS 上游。总览展示实际目标、协议覆盖、业务出口与 DNS 健康；连接详情展示原目标、命中规则、直连/双跳/拒绝、速率和失败阶段。 | 用户可从未接管完成启用、切换、停止。选中 B 不代表 B 已接管；切换会提示 A 恢复原网、长连接可能需重连。关窗不撤规则，重新打开从后台取实际状态。诊断导出不含密码、订阅密钥或未经脱敏的敏感配置。 |
| M5 · 兼容、性能与发布 | 在前述结果之上测试非回环 IPv6、普通 UDP/QUIC、WSL 网络模式、VPN、休眠/重启、升级与卸载。测量并发连接和端口复用下的目标匹配正确率、建连延迟及 Windows/WSL 调用开销。交付支持范围表、安装包和不依赖 UI 的恢复指引。 | 所宣称支持的路径要么按策略转发，要么可证明只对目标阻断；不能保证隔离则拒绝启用严格模式。启动前已建立的 TCP、重启后的首包、转发自容器的流量分别说明，不能概称“全量已保护”。卸载前核实业务和 DNS 均恢复；UI 和日志不得把未测环境显示为已支持。 |

## 切换验收：从 A 切到 B

切换表示**停止 A，再启动 B**，并非迁移连接。释放 A 到启用 B 之间允许没有活动目标；此时两者按各自原网络策略运行。后台将故障阻断或清理未确认的目标仍视为占用唯一接管位置，不能用第二个窗口绕过。

| 情形 | 预期结果 | 核查证据 |
|---|---|---|
| A 正常运行，B 预检失败 | A 不变，B 无规则。 | A 的业务出口和未缓存 DNS 仍走链；B 保持原基线。 |
| 正常 A → B，再 B → A | 预检只读。先核实旧目标恢复，再给新目标落规则；只有新目标的业务与未缓存 DNS 均通过探测才报告切换成功。 | 两个方向均保留阶段记录。旧目标的命令和服务新建连接、DNS 恢复原路径；新目标走链；Windows 对照无变化。 |
| A 有旧连接或无法确认清理 | 能归属的 UDP 映射精确清理，TCP 明示排空/重连。无法证明 A 的规则或映射已清理时，停在“待恢复”，不启动 B。 | 用接管前的 TCP、已代理 TCP 及同一 UDP socket 分别观察，不能只测新连接。 |
| A 已恢复，B 启动失败 | 不自动重新接管 A。B 未落规则则无活动目标；B 已落保护则保留阻断，提示重试或主动恢复 B。 | A 的出口未再次变化；B 不报告健康，不因住宅或 DNS 故障改走直连。 |
| 连点切换、关闭窗口、后台在切换中崩溃 | 同一时间只执行一个写操作；重复请求不重复落规则。重新连接后台后优先核对残留，再允许新的切换。 | 前后台状态一致；按目标与代次核对规则，不误删外部规则；中断恢复过程再执行一次结果不变。 |

## 验收环境与发布证据

- **实验对象：**A 为 `WSLProxyLab-Target`，B 为 `WSLProxyLab-Control`。切换测试中 B 也会成为目标，因此“对照”是当时未被选中的发行版，不是固定名称。另设 Windows 原生请求。不得在日常工作发行版上注入故障。
- **每次验收留三份证据：**操作前基线；运行或故障期间的实际命中、连接去向、接收端请求标记及权威 DNS 记录；停止后的规则归属、监听、解析器及回包路径。缓存命中和客户端超时都不能单独证明结论。
- **发布阻断条件：**非白名单域名的 DNS 直连、任何 DNS 回退到本地或运营商解析、白名单域名的 DNS 在国内上游失败后没有回落双跳、同时接管 A/B、污染未选中发行版或 Windows、误删共享规则、清理未完成却报告恢复、凭据进入日志。任一出现，不发布该版本。
